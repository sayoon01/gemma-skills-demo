## 5. 긍정적 관찰 결과

### 5.1 사용자 요청을 여러 조사 영역으로 분해함

별도 Deep Research Skill이 없는 상태에서도 Gemma4는 하나의 포괄적인 검색어만 사용하지 않고 다음과 같이 조사 범위를 나누었다.

- 피지컬 AI 전체 기술 동향
- 이동·자율주행·작업수행·온디바이스 AI
- 주요 해외 기업 및 제품
- 국내 기업 동향
- VLA 기술
- 상용화 병목
- 시험·검증 요구사항
- 국가로봇테스트필드

따라서 Gemma4 자체에도 기본적인 연구 질문 분해와 검색 query 생성 능력이 있음을 확인하였다.

### 5.2 다수 검색어를 한 Turn에서 호출함

Turn 1과 Turn 2에서 각각 4개의 `web_search`를 호출하여 단일 검색에 의존하지 않고 여러 관점의 자료를 탐색하였다.

### 5.3 요청된 보고서 항목을 대체로 반영함

최종 답변은 다음과 같은 사용자 요청 항목을 중심으로 구성되었다.

- 기술 개요 및 구성
- 주요 기업·제품 비교
- 기술 발전 방향
- 상용화 병목 및 시험·검증 요구사항
- 공용 시험 인프라 시사점

## 6. 주요 한계 및 문제점

### 6.1 실제 원문 페이지를 읽지 않음

가장 중요한 문제이다.

| 항목 | 값 |
|---|---|
| web_search | 8회 |
| fetch_page | 0회 |
| 검색 결과 URL | 40개 |
| 실제 읽은 URL | 0개 |

즉 Gemma4는 웹 검색 결과의 제목과 snippet을 확보했지만, 해당 검색 결과의 실제 페이지 본문을 열어 근거를 검증하지 않았다.

따라서 최종 보고서에 포함된 기업·제품 기능, 기술 단계, 표준, 시장 동향 등의 주장은 원문 근거가 실제로 확인된 상태라고 볼 수 없다.

### 6.2 System Prompt의 원문 확인 지침을 지키지 않음

Runtime은 중요한 사실을 검색 결과 snippet만으로 확정하지 말고 `fetch_page`로 실제 페이지를 확인하도록 지시했지만, Baseline Gemma4는 이를 수행하지 않고 검색 결과만으로 최종 답변을 작성하였다.

이는 일반적인 Prompt만으로는 근거 검증 절차가 안정적으로 수행되지 않을 수 있음을 보여준다.

### 6.3 출처 추적성이 부족함

최종 보고서에는 NVIDIA, Tesla, Figure AI, Boston Dynamics, LG전자, 삼성전자, 현대자동차 등 다수 기업과 제품에 대한 설명이 포함됐지만, 각 주장에 대응하는 실제 URL이나 명확한 출처가 첨부되지 않았다.

`Technology Review, 2024`와 같은 표현도 존재하지만 구체적인 문서명·URL·확인 페이지가 기록되지 않았다.

따라서 독자가 주장별 원문 근거를 다시 추적하기 어렵다.

### 6.4 출처 교차검증을 확인할 수 없음

검색은 여러 번 수행했지만 특정 주장을 두 개 이상의 독립 출처에서 확인했다는 기록이 없다.

다음 과정도 확인되지 않았다.

- 동일 주장에 대한 복수 출처 확인
- 서로 다른 기관 간의 정보 일치 여부 확인
- 상충하는 자료 탐색
- 출처 신뢰도 비교
- 단일 출처 주장 표시

### 6.5 검색 결과의 출처 품질을 체계적으로 관리하지 않음

검색 결과에는 공식 기업 문서뿐 아니라 Wikipedia, 산업매체, 일반 웹페이지 등이 함께 반환될 수 있다.

Baseline에서는 검색 결과가 어느 수준의 출처인지 체계적으로 분류하거나, 1차 출처를 우선하여 원문을 읽는 절차가 확인되지 않았다.

### 6.6 현재 시점과 맞지 않는 작성일 생성

실험은 2026년 9월에 수행되었으나 최종 답변에는 다음과 같이 기록되었다.

- 작성일: 2024년 5월

사용자는 2024년부터 조사 시점까지를 요청했으나, 모델이 조사 시작 시점인 2024년을 현재 작성일처럼 잘못 사용한 것으로 보인다.

이는 별도 검증 절차 없이 모델이 날짜를 생성할 경우 사실 오류가 발생할 수 있음을 보여준다.

### 6.7 사실과 분석을 완전히 분리하지 못함

일부 섹션에는 `(분석자 해석)` 표시가 있으나, 기업 제품의 단계 분류나 공용시험 인프라 효과와 같이 분석적 판단이 포함될 수 있는 내용이 사실 서술과 혼재되어 있다.

### 6.8 조사 종료 기준이 명확하지 않음

총 8회의 검색 이후 추가적인 근거 확인 없이 바로 최종 보고서를 생성하였다.

다음과 같은 종료 판단은 확인되지 않았다.

- 자료가 충분한지
- 아직 확인되지 않은 gap이 무엇인지
- 새로운 검색의 필요성이 낮아졌는지
- 중요 주장에 필요한 복수 출처가 확보됐는지

## 8. Baseline에서 확인된 핵심 특징

Skill OFF 상태에서도 Gemma4는 연구 주제를 여러 검색 영역으로 분해하고 다수의 검색 query를 생성하는 기본적인 조사 행동을 수행하였다.

그러나 검색 결과를 확보한 뒤 실제 원문을 읽지 않고 최종 답변을 생성했으며, 주장별 출처 추적, 독립 출처 교차검증, 출처 신뢰도 평가, 반대 근거 탐색, 미확인 사항 관리와 같은 심층조사 절차는 확인되지 않았다.

따라서 이번 Baseline은 다음 가설을 검증하기 위한 기준으로 사용한다.

> deep-research Agent Skill을 적용할 경우 Gemma4의 단순 검색 중심 행동이 실제 원문 읽기, 출처 평가, 교차검증, gap 추적, structured citation 중심의 조사 행동으로 변화하는가?

## 9. Skill ON 비교 시 확인할 항목

동일 조건으로 deep-research Skill을 활성화한 뒤 다음 항목을 비교한다.

### 정량 비교

- Turn 수
- 전체 Tool Call 수
- web_search 호출 수
- fetch_page 호출 수
- 고유 검색 URL 수
- 실제 읽은 고유 URL 수
- Tool 오류 수
- 최종 답변 길이
- 전체 실행시간
- Prompt/Eval token 수

### 조사 행동 비교

- 연구 주제를 4~8개 sub-goal로 명시적으로 분해하는가
- 하나의 sub-goal에 복수 query를 사용하는가
- 검색 결과 이후 실제 원문을 `fetch_page`로 읽는가
- 1차·고신뢰 출처를 우선하는가
- 중요한 주장을 2개 이상의 독립 출처로 교차검증하는가
- 단일 출처 주장에 한계를 표시하는가
- 상충하는 자료를 별도로 기록하는가
- 확인하지 못한 사항을 Gap으로 기록하는가
- 출처 URL을 최종 보고서에 남기는가
- Skill에서 정의한 보고서 구조를 따르는가

### B1 호환성 한계

현재 실행 환경에는 별도의 Agent 또는 sub-agent 실행 도구가 제공되지 않는다.

따라서 Skill ON 시험은 deep-research의 전체 원본 기능을 검증하는 것이 아니라 다음 기능을 우선 검증하는 **B1 Partial Compatibility Test**로 정의한다.

- SKILL.md 인식
- 연구 계획 및 질문 분해
- 검색 규율
- 원문 읽기
- 출처 우선순위
- 교차검증
- 근거 중심 보고서 구조

원본 Skill에서 요구하는 병렬 sub-agent와 multi-wave convergence 기능은 후속 B2 시험에서 별도로 검증한다.
