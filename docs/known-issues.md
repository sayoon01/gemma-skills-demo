# 확인된 문제와 조치 계획

## 1. 기존 엑셀 읽기 후 분석 답변 미완료 (약 32K context)

### 대상 실행
- 실행 ID: run-hb_2vzzc
- 모델: gemma4:31b
- 스킬: xlsx

### 실제 결과
- 입력 파일 2개의 구조 확인 성공
- 입력 파일 2개의 지정 범위 읽기 성공
- 도구 오류 0건
- 원본 파일 해시 유지
- 최종 답변은 분석 결과 대신 원칙 설명과 파일 재요청으로 종료

### 상태 판정 문제
실행기는 도구 호출과 최종 응답 종료 여부만 검사하여
read_analysis_completed로 기록했다.

실제 판정은 "파일 읽기 성공, 요청한 분석 미완료"이다.
원본 실행 기록은 수정하지 않고 이 문서에 정정 내용을 남긴다.

### 진단
범위 읽기 결과에 셀별 메타데이터가 반복되어 입력이 커졌다.
데이터 추가 후 prompt_eval_count가 감소하는 현상이 관찰됐다.

컨텍스트 잘림 또는 대화 유지 문제 가능성이 있으나,
서버 내부에서 어떤 메시지가 유지되었는지는 확정하지 못했다.

## 2. 64K context에서 최종 분석 Timeout

### 대상 실행
- 실행 ID: run-k_b3sp0q
- 모델: gemma4:31b
- 설정: `num_ctx=65536`, `num_predict=4096`
- 스킬: xlsx

### 실제 결과
- CONTEXT 65536 적용 확인
- 도구 호출 4회까지 진행 (구조 확인·범위 읽기)
- 3번째 모델 호출에서 HTTP ReadTimeout 300초
- 이전처럼 요청을 잊은 형태가 아니라, 대량 tool 결과 처리 시간 초과로 판단

### 해석
- Skill 적용(지침 로드·도구 자율 선택·파일 읽기)은 확인됨
- 병목은 Skill 지원이 아니라 Runtime 효율(tool 결과 크기·처리 시간)
- timeout만 늘리는 재시도는 좋은 실증이 아님

공개 요약: [evidence/xlsx-runtime/README.md](evidence/xlsx-runtime/README.md)

## 수정 계획 (xlsx는 기록만, 즉시 심화 최적화하지 않음)

1. 셀별 반복 메타데이터를 줄여 도구 결과를 compact하게 전달한다.
2. 원본 셀 위치와 자료형은 필요한 범위에서 보존한다.
3. 데이터 수집과 최종 분석 단계를 분리한다.
4. 최종 분석 요청에 원래 사용자 요청을 다시 포함한다.
5. 모델 컨텍스트와 출력 제한을 명시적으로 설정한다.
6. 파일 읽기 완료와 분석 검토 완료를 구분한다.
7. 이후 실험은 community deep-research Skill로 전환한다.

## 공개 범위
실제 업무 데이터가 포함된 원본 로그는 outputs에 보관한다.
공개 저장소에는 기술적 현상과 수정 내용만 기록한다.
